# Interface and user flows

## Navigation
| Panel | Main controls and information |
|---|---|
| Home | Voice input, task input, active jobs, daily next actions |
| New research | Product, problem, location, exclusions, depth, editable generated brief |
| Leads | Business/contact/fit columns, review filters, coverage summary |
| Lead detail | Contacts first, identity, evidence, need analysis, alternatives, history |
| Assistant | Transcript, current context, tool actions, stop, result popup |
| Files and memory | Approved folders, indexing health, search, editable memory |
| Mistakes and learning | Report queue, datasets, experiments, promotion, rollback |
| Hardware and models | Specs, benchmark results, recommendation reasons, resource controls |
| Integrations | Connection status, permissions, quotas, cost and disconnect |
| Activity | Job progress, errors, retries, actions and audit history |

## Lead card rules
No single green 'verified' badge that conflates identity, contact and interest. Show explicit states separately. A clickable contact reveals the source and verification method. A disputed contact cannot be copied into automated outreach without resolving the dispute. Export preserves labels and dates.

## File popup
Show up to three matches with preview and location. Buttons: Open, Show folder, This is correct, Wrong file. Allow a corrected file selection. Show 'No reliable match' rather than a fabricated path.

## Correction flow
Report mistake → category → expected answer/file/contact (optional) → evidence/comment → scope → save. Display immediate effect, such as 'This contact is excluded from outreach'. Offer 'Use for training' separately, off for sensitive content. Later show whether the correction helped a benchmark.

## Visibility and accessibility
Keyboard navigation, clear focus states, readable status text and screen-reader labels. Do not use colour alone for confidence. Distinguish queued from running from waiting for user input. Resource profile should be understandable: 'Light', 'Balanced', 'PC worker', with measured details available.

## Product language
Use 'Source says', 'Observed', 'Inferred', 'Unknown', and 'Confirmed by interaction'. Avoid claiming a guaranteed sale. Keep internal model/tool jargon out of normal flows except hardware settings and the learning panel where it is useful.
