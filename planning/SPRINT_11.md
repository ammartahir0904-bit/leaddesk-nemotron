# Sprint 11 — learning review and versioned local datasets

Date: 20 October 2026, Asia/Karachi. B14's reviewed-data and deletion slice from the Sprint 10 handoff. Automated verification passed; browser and representative real-source acceptance remain unverified. Training, experiments, model promotion and rollback execution are outside this slice.

## User outcome

Open Learning and datasets, review an existing contact correction or completed quality-unit audit, redact its example text, record the reviewer/source permission/permitted local use, then include or exclude it. Select reviewed revisions and freeze a version with a reproducible JSON manifest. Export only while its sources and permissions remain current. Delete or change an example to invalidate affected versions and remove their copied payloads without changing research or contact suppression.

## Delivered

- **Review queue and dashboard:** real/synthetic source modes, available source and included/excluded review counts, saved version count, links to original research/quality audits. Current pass/fail contact/factual-unit audits and contact feedback are candidates; unknowns and private file/memory/screen/audio sources are not automatically eligible. Sources/examples/versions have independent stable 20-item pagination; example selection spans pages.
- **Explicit human labels:** manually edited input/observed/expected output, cited saved evidence, reviewer, decision reason, source-permission basis and default evaluation-only or explicit local-training scope. Redaction acknowledgement is required and reset on UI edits. Obvious credential assignments/private-key headers are rejected; the check is conservative and incomplete, and does not replace manual redaction. Suggested replacement contacts stay unverified source feedback, never automatic labels or live contact facts.
- **Optimistic review revisions:** source hash/revision binding, source freshness checks, current review revision checks and idempotent writes. Newer contact feedback supersedes older candidates. A changed quality audit or changed current prediction state makes the prior learning example stale. Exclusion clears example fields and invalidates copied version payloads. User labels remain explicit human judgements, not independently verified truth.
- **Frozen versions:** up to 100 distinct included current examples, separate real/synthetic modes, development/holdout split and evaluation/training-preparation purpose. A training-purpose version requires explicit local-training scope on every member; holdouts cannot be training-purpose. Manifest includes stable dataset/member hashes, exact review/source revisions, source origin, cited evidence IDs/body hashes/retrieval times, review timestamp, human-label provenance, permission basis and use scope. Only edited review fields are copied; raw source comments, unverified suggestions and full source URL paths/queries are excluded. No training executes.
- **Leakage and duplicates:** reject repeated source targets or identical normalized reviewed examples inside one version. Reserve domain groups, exact copied-page hashes, target hashes and optional reviewer-defined shared business groups across development/holdout versions. Existing quality holdouts and their comparison sources are protected; newly introduced quality holdout conflicts invalidate old development versions on inspection/export. Domain grouping uses the final two DNS labels conservatively, so `co.uk`-style suffixes may over-group unrelated sites. Multi-domain businesses/near-duplicate sources need manual shared grouping; time metadata supports manual chronological selection rather than an automatic temporal split.
- **Deletion/withdrawal:** editing, excluding, changing permission or deleting an example invalidates all versions containing it and clears every copied member payload in those versions. Missing/changed sources and split conflicts are rechecked when listing/inspecting/exporting versions. Invalidated versions cannot export and do not recover automatically. Version deletion removes its members but leaves source examples. Example deletion preserves original feedback/research/suppression. Hash-only request receipts block resurrection through replay; hash-only split exposure reservations persist after deletion. Already downloaded/in-flight material, backups and physical SQLite/WAL erasure are outside these app-level controls.
- **Bounded local operation:** authenticated routes retain existing host/origin/no-store and 16,000-byte JSON limits. At most 2,000 saved example reviews, 200 versions, 100 members/version and 2 MiB/export. Writes, failure rollback, receipts and split reservations are transactional. Migration 008 adds isolated learning tables and preserves previous storage. No dependency/runtime/model was installed, no source/model call is made by learning, and no cloud or remote worker is enabled.

## Remaining desktop acceptance

Use a normal desktop terminal and a separate empty data directory. Stop a regular instance on port 8765, then run `LEADDESK_DATA_DIR="$PWD/.local/browser-check" ./launch.sh`. In another terminal, run `cd apps/web` and `LEADDESK_TEST_TOKEN_FILE=../../.local/browser-check/access-token npm run test:e2e:learning`.

The prepared fictional browser check creates a synthetic demo/contact correction, confirms no automatic inclusion, edits/redacts a review, checks that further edits reset redaction acknowledgement, rejects training-purpose preparation under evaluation-only permission, freezes/inspects/downloads JSON, deletes the reviewed example, checks version invalidation and blocked export, confirms original suppression, deletes the version and checks mobile overflow/page errors. It cleans its example/version/download where possible and leaves the original synthetic research/correction in the disposable database. It has not run past Chrome launch here.

Separately exercise keyboard navigation, multiple review/example/version pages, source/audit edits in another tab, lost-response retry, exclusion, consent withdrawal, existing/late holdouts, changed/deleted sources and export failures.
