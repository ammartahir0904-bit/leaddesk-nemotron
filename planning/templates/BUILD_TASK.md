# Implementation task template

## Outcome
What can the user do after this task?

## Scope
Backlog ID, modules touched, dependencies and excluded later work.

## Inputs and outputs
Typed request, persisted objects, evidence requirements and visible states.

## Failure handling
Timeout, missing data, cancellation, disputed facts, permissions and retry behaviour.

## Acceptance checks
List meaningful normal and failure scenarios. Use synthetic fixtures with explicit labels; keep live-source tests separate.

## Resource and quality report
Hardware/config, sample count, actual timings/memory, correctness results and unresolved limitations.

## Completion record
Changed files, how to run, tests actually executed, results, migration notes and next task. Never claim unexecuted checks passed.
